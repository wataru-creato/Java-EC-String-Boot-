## 学んだことまとめ
9/8
- DockerとホストPCのポートの意識
Dockerコンテナ内部の標準ポート（3306）と、PC（ホスト側）からアクセスするための窓口となるポート（3307）が異なるため、接続先URLではPC側のポートを指定する必要があることの理解。

- タイムゾーン指定の厳密さ
JST のような曖昧な短縮名ではJavaやMySQLが正しく解釈できないため、Asia/Tokyo のように都市名を含めた正確な指定が求められるという仕様の背景。

- リポジトリファイルの個別作成ルール
Spring Bootでは複数のリポジトリを1つのファイルにまとめることはできず、テーブルごとに独立した JpaRepository のインターフェースファイルを1つずつ作る必要があるという基本構造の把握。

- 日付データへの LocalDate 型の適用
日付を int や String で持たせると比較やバリデーションで破綻するため、LocalDate 型と LocalDate.of() を使って安全に型を一致させるアプローチ。

- データベースの「予約語」によるテーブル競合の回避
order のようにSQLのシステム命令と被る単語をそのままエンティティ名にするとテーブルが作成されないため、@Table(name = "orders") を使って物理名を変えるという実務的な回避策。

- idはLongを使う型もある

- 処理の流れは外部のリクエスト→Controller(指示だし)→Service（ロジックの記載）→Repository（DB操作）→Datebase
  
- 戻り値の voidは、idを削除したときなどのデータを返さない処理の際に、Javaの「必ず型を宣言する」ルールに対して「何も返さない」ことを明示する仕組みである。
  
- save()はUPDATE、INSERTそれぞれ自動的にチェックしているので新規作成と更新はどちらもsave()を使う。

- Privateとpublicの使い分け判断、今回はその階層以外でも使われるのかを判断して使い分ける
